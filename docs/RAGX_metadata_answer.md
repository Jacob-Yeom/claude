# Konan RAG-X 3.0 메타데이터 처리 · 지식 영역 확인 사항 답변

- 근거 문서: Konan RAG-X 3.0 매뉴얼(설치·운영 가이드, 58쪽)
- 작성일: 2026-10-08
- 표기 기준
  - ● 매뉴얼에 명시되어 확인됨
  - ◐ 제품 구조상 가능하나 매뉴얼에 방식이 명시되지 않음 (R&D 확인 또는 커스텀 필드로 구현)
  - ○ 매뉴얼에 기재 없음. 현 제품 기능으로 보기 어려움 (R&D 확인 또는 커스텀 개발)

## 0. 전제 (먼저 짚을 문제)

1. 제공된 PDF는 **설치·운영 매뉴얼**이지 설계서가 아니다. 따라서 "처리 가능 여부"는 매뉴얼에 드러난 범위에서만 확정할 수 있고, 나머지는 R&D 확인 항목으로 분리해야 한다.
2. RAG-X의 데이터 단위는 **청크 행(row) 테이블(볼륨)** 하나다. 문서 테이블과 청크 테이블이 분리된 구조가 아니다. 문서 단위 메타는 각 청크 행에 반복 저장(비정규화)된다.
3. 권한 관리 단위는 **소스(볼륨 묶음)** 이며, 문서 단위 권한·보안등급·상태 플래그는 없다.
4. 커스텀 필드(업무 메타)는 **덤프파일(FGF) 또는 데이터베이스 가져오기**에서만 매핑할 수 있다. 문서파일 직접 업로드 경로에는 커스텀 필드 매핑 UI가 없다.

### 볼륨 기본 필드 (매뉴얼 p.36, p.45)

| 필드 | 타입 | 의미(매뉴얼 기준) |
|---|---|---|
| cid | STRING (PK) | 청크 ID |
| uuid | STRING | 문서 ID |
| prev_cid / next_cid | STRING | 앞·뒤 청크 연결 |
| title | TEXT | 문서 제목 (필수, 검색 대상) |
| chunk | TEXT | 청크 본문 (필수, 임베딩 대상) |
| c_vec | VECTOR(1024) | 청크 임베딩 벡터 |
| pgno | INT32 | 페이지 번호 |
| filepath | STRING VERBATIM | 원본 경로 |
| chkoff / chkno | INT32 | 청크 오프셋 / 청크 번호 |
| chnklen | INT32 | 청크 길이 |
| c_kwd / c_ngram | STRING LIST / STRING | 키워드 / n-gram (키워드 검색용) |
| tag, dt, tm, lines, fmt | 각종 | 매뉴얼에 의미 설명 없음 |

기능성 커스텀 필드(p.46): `createdAt`(TIME, 기간 필터·정렬 활성), `url`(STRING, 출처 원문 링크 활성).

## 1. RAG 메타데이터 처리

### 1-1. 문서 단위 메타

| 항목 | 판정 | 근거 / 비고 |
|---|---|---|
| 문서명 | ● | 기본 필드 `title`. 덤프/DB 경로에서는 `file_name` 커스텀 필드 예시 있음(p.48) |
| 파일 유형 | ◐ | 기본 필드 `fmt`(INT8)가 있으나 의미 미기재. 커스텀 필드로 확장자 저장 가능 |
| 원본 경로 | ● | 기본 필드 `filepath`. 커스텀 `file_path` 예시도 있음 |
| 버전 | ○ | 버전 필드·버전 관리 기능 없음. 커스텀 필드 `version` + PK 설계로 대체 |
| 작성일 | ● | `createdAt` 커스텀 필드(YYYYMMDDHHmmss) → 검색 기간 필터·최신순 정렬 활성 |
| 등록자 | ◐ | `writer` 커스텀 필드 예시 있음. 업로드 계정을 시스템이 자동 기록하는 기능은 미기재 |
| 보안 등급 | ○ | 문서 단위 보안등급 필드·필터 없음. 대안: 등급별 볼륨 분리 + 소스 권한 |
| 공유 범위 | ○ | 문서 단위 없음. 소스별 사용자/그룹 권한(p.18~20)으로 대체 |
| 사용 상태 | ○ | 활성/미사용 플래그 없음. DELETE 작업으로 볼륨에서 제거하거나 커스텀 필드 + 검색 API 필터 커스터마이징 필요 |

### 1-2. 청크 단위 메타

| 항목 | 판정 | 근거 / 비고 |
|---|---|---|
| 페이지 | ● | `pgno` |
| 문단 | ◐ | `chkno`, `chkoff`, `prev_cid/next_cid`로 위치·순서 추적 가능. 문단 단위 식별자는 아님(오프셋 기반) |
| 표 | ○ | 표 구조·위치 메타 없음. DocAI 텍스트 변환 결과가 chunk에 섞여 들어가는 수준 |
| 이미지 | ○ | 이미지 메타 없음. 텍스트 변환 기반 |
| 회로도 위치 | ○ | 없음. 회로도는 이미지/CAD 기반이라 텍스트 변환 자체가 안 될 가능성이 높음 (OCR 지원 여부 미기재) |
| 섹션명 / heading | ○ | 기본 필드 없음. 커스텀 필드로 넣으려면 전처리에서 추출해 FGF에 실어야 함 |
| chunk id | ● | `cid`(PK), 문서는 `uuid` |
| embedding id | ◐ | 별도 ID 없음. `c_vec`가 청크 행에 인라인 저장되므로 `cid`가 곧 임베딩 키 |

### 1-3. 업무 메타 (제품명, PBA명, 부품 Ref. Des., 시험 항목, 측정값, 불량 유형, 고객사, 접수번호, 단계)

판정: **◐ 저장은 가능, 필터는 제한적**

- 저장: 모두 커스텀 필드로 저장 가능. STRING / TEXT / INT / TIME / STRING LIST 타입 지원, 정제 설정(NULL 처리, 최소·최대 범위, 개인정보 마스킹) 적용 가능(p.47~49). 측정값 같은 수치는 범위 정제 옵션이 있다.
- 조건 1: **덤프파일(FGF) 또는 DB 가져오기** 경로로만 매핑 가능. 고객 MES/QMS/문서관리 DB 테이블에서 가져오거나, 전처리로 FGF를 생성해야 한다. DB 경로에서는 "문서필터" 체크로 경로의 문서 파일을 가져와 본문(Contents)으로 청킹할 수 있다(p.41).
- 조건 2: RAG-X UI에서 커스텀 필드로 **검색 범위를 좁히는 필터는 `createdAt`(기간)만** 제공(p.26~28). 제품명·고객사·단계로 필터링하려면 (a) 소스(볼륨) 분리, (b) 검색 API 레벨 필터 커스터마이징 중 택일. (b)의 지원 여부는 R&D 확인 필요.
- 설계 쟁점: 업무 메타가 문서 단위인지 청크 단위인지 설계서에 명시해야 한다. 볼륨은 청크 행 테이블이므로 문서 메타는 모든 청크 행에 반복 저장된다.

### 1-4. 검색 메타

| 항목 | 판정 | 근거 / 비고 |
|---|---|---|
| 벡터 유사도 | ◐ | 유사도 기준(threshold, 0.001~1.0, 기본 0.7) 설정 가능. 결과별 점수 **표시**는 화면에 없음 |
| 키워드 매칭 | ● | 자연어 검색 결과 하이라이트, `c_kwd`/`c_ngram` 필드 |
| 필터 조건 | ◐ | 검색필드(전체/제목), 정렬(정확도/최신), 기간(createdAt)만. 임의 커스텀 필드 필터 UI 없음 |
| 권한 필터 | ● | 검색 시 access 모듈이 권한 검사, 권한 있는 소스만 선택·노출(p.4, p.23) |
| 검색 범위 | ● | 소스 선택(복수 볼륨), 나의 저장 공간(개인 첨부), LLM 직접 질문 |
| Top-K 결과 | ○ | 설정값·표시 미기재. 출처 카드 수("View N more")로만 노출 |
| 재랭킹 점수 | ○ | Reranking 모델 사용은 확인(키워드+벡터 결과를 리랭킹, p.26). 점수 표시 미기재 |

### 1-5. 답변 메타

| 항목 | 판정 | 근거 / 비고 |
|---|---|---|
| 출처 문서 | ● | 출처 카드 → 클릭 시 참고문서 전문 팝업(p.25). `url` 필드 있으면 원문 링크 |
| 근거 위치 | ◐ | `pgno`/`chkoff`/`chkno`가 데이터에는 있으나 채팅 화면에 페이지·위치 표시는 없음 |
| 신뢰도 | ○ | 없음 |
| 답변 보류 사유 | ○ | 없음. "RAG-X는 실수할 수 있습니다" 고지 문구만 |
| 참조된 청크 | ◐ | 출처 카드는 문서 단위. 청크 단위 노출 미기재 |
| 후속 질문 추천 근거 | ○ | 후속 질문 추천 기능 자체가 매뉴얼에 없음 |

### 1-6. 설계서 반영 방식 제안

설계서에는 아래 4개 레이어로 나누어 메타 항목을 매핑할 것을 제안한다.

1. **볼륨(청크 테이블) 스키마**: 기본 19필드 + 커스텀 필드 목록(필드명 / 타입 / 필수 여부 / 정제 규칙 / 출처 시스템). 문서 메타는 청크 행에 비정규화된다는 점을 명시.
2. **원본 메타 저장소(RAG-X 외부)**: 문서 단위 메타(버전, 보안등급, 공유범위, 사용상태, 등록자)는 고객 문서관리 DB 또는 RAG-X PostgreSQL의 별도 테이블에 두고, 덤프/DB 가져오기로 볼륨에 주입하는 흐름을 정의.
3. **응답 DTO**: 현 제품 응답은 "출처(title, url, 전문) + 답변" 수준. 청크별 pgno / chkno / 유사도 / 리랭킹 점수를 응답에 포함하려면 service 모듈 API 확장이 필요. R&D 확인 항목.
4. **화면 표시 항목**: 출처 카드에 페이지 번호, 업무 메타 뱃지(제품명/접수번호 등) 노출은 UI 커스터마이징 범위.

## 2. 지식 영역 확인 사항

| # | 확인 사항 | 판정 | 답변 |
|---|---|---|---|
| 1 | 원본 파일 메타와 청크 메타 동시 저장 | ◐ | 덤프/DB 경로에서는 문서 메타가 커스텀 필드로 각 청크 행에 함께 저장된다. 문서파일 직접 업로드는 기본 필드(title, filepath, pgno 등)만 저장된다. 문서·청크 테이블 분리 구조는 아니다. |
| 2 | 보안등급 · 공유범위 · Q&A 참조 여부 · Agent 사용 여부 분리 관리 | ○ | 문서별 플래그 없음. 관리 단위는 소스(볼륨)와 사용자/그룹이다. Agent 개념은 매뉴얼에 없다. 대안: 용도별(Q&A용/Agent용)·등급별 볼륨 분리 + 소스 권한. |
| 3 | 파일 유형별 메타 추출 | ◐ | 채팅 첨부 지원 확장자: pdf, docx, doc, txt, xls, xlsx, hwp, hwpx, ppt, pptx(p.22). 색인 작업의 지원 확장자 목록은 미기재("미지원 형식 자동 차단", 30MB 제한). DocAI 필터는 DRM 해제 + 텍스트 변환(p.4). 이미지·회로도 OCR 지원 여부는 미기재. 추출 메타는 텍스트 + 페이지 번호 수준이며 표·이미지 구조 메타는 없다. |
| 4 | 회로도·표 위치 출처 표시 | ○ | 페이지 번호(pgno)까지만 가능. 표·도면 내 좌표(bbox) 없음. 대안: 회로도를 시트/페이지 단위로 분리해 페이지를 위치로 사용하거나, 별도 전처리(OCR + 좌표 추출)로 위치 메타를 커스텀 필드에 저장. |
| 5 | 문서 버전 변경 시 임베딩/온톨로지 갱신 | ◐ | 임베딩: `UPDATE_OR_INSERT`(PK 기준)로 재색인 가능하고 증분 기준컬럼(updatedAt 등)으로 변경분만 수집 가능(p.37). 단 PK가 청크 단위(cid)라 재청킹 시 청크 수가 달라지면 잔존 청크가 남을 수 있다. 따라서 **문서 uuid 기준 DELETE 후 INSERT** 정책을 권고. 온톨로지: 매뉴얼에 온톨로지/지식그래프 기능 없음. 외부 설계 영역. |
| 6 | 삭제 · 미사용 전환 · 권한 변경 시 즉시 제외 | ◐ | 권한 변경: 소스 권한은 검색 시 access 모듈이 검사하므로 구조상 즉시 반영(단 문서 단위 권한 없음). 삭제: DELETE 작업(PK 기준) 실행 후 반영되며 즉시 색인 실행 버튼이 있다(p.52). 즉시성은 작업 실행 시점에 의존. 미사용 전환: 상태 플래그 없음, 삭제 또는 별도 볼륨 이동으로 처리. 개인 첨부("나의 저장 공간") 삭제 방법은 미기재. |
| 7 | 설계서에 파이프라인·메타 추출·권한·버전 정책 포함 필요 여부 | 필요 | 위 1~6 중 제품이 직접 제공하는 것은 소스 권한과 PK 기반 재색인뿐이다. 나머지는 전처리·정책·커스터마이징 영역이므로 설계서에 반드시 포함해야 한다. |

설계서에 포함할 항목:
- 문서 처리 파이프라인: 수집(DB/FGF/파일) → DocAI 변환 → 청킹(Chunk Size 2048 / Overlap 256 기본값) → 정제 → 임베딩(1024차원) → 색인 스케줄
- 메타 추출 방식: 파일 유형별 추출 가능 메타 표, 회로도·이미지 처리 방식(OCR 여부, 페이지 단위 분리)
- 권한 처리: 소스(볼륨) 설계 기준(보안등급 × 용도), 사용자/그룹 매핑, 기본 그룹 정책
- 버전 관리 정책: PK 설계(문서ID + 버전 + 청크번호), 갱신 연산(DELETE→INSERT vs UPDATE_OR_INSERT), 증분 기준컬럼, 이전 버전 보존 여부

## 3. 고객 회신 전 R&D 확인 질문 (우선순위 순)

1. 색인 작업(문서파일/서버 문서파일)의 지원 확장자 전체 목록과 이미지 OCR 지원 여부
2. 문서파일 업로드 경로에서 커스텀 필드를 넣는 방법 (현재 UI 없음 → FGF 변환이 필수인지)
3. 검색/채팅 API 응답 스펙: 청크별 pgno / chkno / 유사도 / 리랭킹 점수 포함 여부
4. 커스텀 필드 기반 필터(제품명, 고객사 등)를 검색 API에서 지원하는지 (UI에는 없음)
5. 기본 필드 `fmt`, `dt`, `tm`, `tag`, `lines`의 정확한 의미
